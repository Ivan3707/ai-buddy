# AI-buddy: расширение Chrome (персонаж Бади)

Расширение Manifest V3 для Chrome 116+. Основной интерфейс — персонаж **Бади** на каждой странице с окном чата. Виджет общий с веб-приложением: `buddy/widget.js` (вид) и `lib/gateway.js` (связь с backend). Боковая панель (`chrome.sidePanel`) остаётся для служебных страниц Chrome, где персонаж не может появиться.

Все данные синтетические: в шапке стоит бейдж «демо», у ссылок на источники — пометка «(демо)». Инструкции из демо-базы знаний не являются регламентами Авито.

## Возможности

- **Вход.** Email и пароль, JWT хранится в `chrome.storage.session` и удаляется при закрытии браузера или по кнопке «Выйти». Логика сессии лежит в `popup-session.js`, клиент для логина — в `packages/client`.
- **Потоковый чат.** `POST /api/chat/stream` (SSE). Текст ответа появляется по мере генерации. Строка статуса показывает этап: «Ищу в базе знаний…», «Пишу ответ…», «Готовлю заявку…». Источники выводятся ссылками, цитата видна во всплывающей подсказке. При ошибке появляется сообщение и кнопка «Повторить». Пока идёт ответ, поле ввода заблокировано. `conversation_id` хранится в `chrome.storage.session`, кнопка «Новый диалог» его сбрасывает.
- **Действия.** Если в ответе есть событие `action`, показывается карточка с параметрами заявки и кнопками «Подтвердить» и «Отменить». Без нажатия «Подтвердить» ничего не выполняется. После подтверждения видны номер и статус заявки или сообщение «вопрос передан наставнику».
- **Оценка ответа** 👍/👎 (`POST /api/chat/messages/{id}/feedback`). Кнопки появляются, когда backend прислал `meta.message_id`.
- **Контекст страницы.** Переключатель «Учитывать открытую страницу» включён по умолчанию. К вопросу прикладывается `page_context {url, title, selection}` активной вкладки. Под переключателем видно, какая страница будет отправлена.
- **Бриф.** Если диалога ещё нет, при открытии панели раз в день для каждого пользователя вызывается `POST /api/chat/brief/stream`. Это проактивная подсказка о следующем шаге.

## Персонаж Бади на страницах

Основной интерфейс расширения — персонаж **Бади**: маленький робот в правом нижнем углу каждой страницы. Его можно перетащить мышкой, и он запоминает место. Клик открывает окно чата рядом с ним. У окна два режима — компактный и полноэкранный (⤢/⤡); размер каждого меняется за угол и запоминается в браузере (`chrome.storage.local`). Источник под ответом открывает документ базы знаний прямо в окне (`GET /api/kb/docs/{id}`) с подсветкой цитаты; «Открыть документ полностью» ведёт в демо-вики.

- **Проактивность.** При первом появлении за день Бади здоровается и предлагает сводку (бриф). На страницах дашбордов, трекера задач, ревью и вики он подсказывает по теме страницы: «Это дашборды метрик. Подсказать, что смотреть в первую очередь?». Когда меняется статус заявки (например, наставник согласовал отпуск), Бади сообщает об этом в пузыре.
- **Выделенный текст.** Выделите фразу на странице, и Бади предложит «Это актуально?». Вопрос уйдёт вместе с выделением, и бот сверит его с базой знаний.
- **Состояния.** Бади думает (мигает антенна), говорит, пока печатается ответ, ждёт подтверждения (значок «!» у карточки), радуется успеху и грустит при ошибке. Если в системе включено «уменьшение движения», анимация отключается.
- **Безопасность.** Персонаж живёт в закрытом shadow DOM: стили сайта его не ломают, а скрипты страницы не видят его содержимое. Токен остаётся в фоновой части расширения (`background.js`), на страницу он не попадает. Страница получает только имя пользователя для приветствия и готовый к показу текст. Текст ответа экранируется перед разметкой. URL уходит без query и якоря.
- **Где появляется.** На всех `http(s)`-страницах сразу. На веб-приложении AI-buddy (`:5173`) Бади из расширения заменяет встроенный виджет сайта, а сайт передаёт ему свои подсказки через `window.postMessage` (принимается только текст и только с origin сайта). Клик по иконке расширения открывает и закрывает чат Бади на текущей вкладке. На служебных страницах (`chrome://`, магазин расширений) скрипты запрещены, поэтому там иконка открывает боковую панель. Кнопка «Убрать» в панели отключает Бади на этом сайте, «Показать» включает обратно. Крестик на персонаже скрывает его до закрытия вкладки, клик по иконке возвращает.

Логика персонажа (подсказки, статусы заявок, модель отображения, ограничение позиции) лежит в `lib/buddy.js` и покрыта тестами. Сам `buddy/content.js` только рисует.

## Сборка

```sh
npm ci
npm run build --workspace @ai-buddy/extension
```

Результат сборки лежит в `apps/extension/dist`. Origin backend задаётся при сборке и попадает в `host_permissions`, CSP (`connect-src`) и `config.js`. По умолчанию используется `http://127.0.0.1:8080`. Если порт 8080 занят и backend поднят с `BACKEND_PORT=18080`:

```sh
BACKEND_ORIGIN=http://127.0.0.1:18080 npm run build --workspace @ai-buddy/extension
```

```powershell
# PowerShell
$env:BACKEND_ORIGIN = 'http://127.0.0.1:18080'; npm run build --workspace @ai-buddy/extension
```

Разрешён только origin вида `http://127.0.0.1:<port>`. В конце сборки проверяется, что `manifest.json` — валидный JSON и все файлы, на которые ссылаются манифест, HTML и импорты модулей, лежат в `dist`.

## Установка и запуск

1. Откройте `chrome://extensions` и включите «Режим разработчика».
2. Нажмите «Загрузить распакованное расширение» и выберите `apps/extension/dist`. После пересборки нажмите на карточке расширения кнопку обновления ↻.
3. Закрепите AI-buddy на панели и нажмите на иконку: справа откроется боковая панель. Её также можно выбрать в меню боковой панели Chrome.
4. Войдите учётной записью из основного README. Backend должен быть запущен.

## Разрешения и зачем они нужны

| Разрешение | Зачем |
|---|---|
| `sidePanel` | Чат в боковой панели на служебных страницах (`chrome://`), где персонаж не может появиться: клик по иконке. |
| `storage` | `storage.session`: JWT и `conversation_id`, очищаются при закрытии браузера. `storage.local`: настройка переключателя и дата последнего брифа. |
| `activeTab` | Временный доступ к URL и заголовку **только той вкладки**, на которой пользователь нажал иконку расширения. Доступ действует, пока вкладка не перешла на другую страницу или не закрыта. |
| `scripting` | Прочитать выделенный текст (`getSelection()`) на вкладке, к которой есть доступ через `activeTab`. Скрипт выполняется однократно при отправке вопроса и ничего не меняет на странице. |
| `host_permissions: http://127.0.0.1:<port>/*` | Запросы к локальному backend и только к нему. |
| `host_permissions: http(s)://*/*` | Показывать Бади на любом сайте без отдельного запроса. Сам персонаж страницу не читает: заголовок, URL и выделенный текст уходят в чат, только когда пользователь задаёт вопрос с включённым «Учитывать эту страницу». |

**Компромисс с правами.** Раньше Бади включался на каждом сайте отдельно, с запросом разрешения. Это строже, но персонаж, которого надо сначала «включить», плохо работает как помощник: стажёр о нём забывает. Поэтому Chrome при установке предупреждает, что расширение «читает и изменяет данные на всех сайтах». В корпоративной установке список сайтов сужается до внутренних доменов (вики, трекер, Grafana) в `host_permissions` и `matches`. Разрешение `tabs` не запрашиваем. Боковая панель получает контекст вкладки через `activeTab`, только если пользователь сам нажал иконку на этой вкладке. Ограничение такое: после перехода на другую страницу или вкладку доступ пропадает. Панель тогда пишет «Нет доступа к этой вкладке. Нажмите на иконку AI-buddy…» и отправляет вопрос без контекста. Чтобы снова выдать доступ, достаточно ещё раз нажать иконку.

**Что никогда не отправляется:**

- страницы `chrome://`, `edge://`, `about:`, `file://`, `chrome-extension://`, `view-source:`, `data:` — передаются только `http(s)`;
- логин и пароль из URL, якорь `#…` и query-параметры, похожие на секреты (`token`, `code`, `key`, `password`, `session`, `signature` и т. п.).

Поля обрезаются по лимитам контракта: URL — 2000 символов, title — 300, selection — 2000. Если переключатель выключен, вкладки не опрашиваются. Backend и AI обязаны считать `page_context` данными, а не инструкциями (защита от prompt injection).

## Совместимость с текущим backend (fallback)

Сейчас backend реализует только `POST /api/chat`. Новые эндпоинты делаются по контракту `contracts/backend.openapi.json` в ветке `feat/ai-features`. Расширение уже работает с текущим backend:

| Ситуация | Поведение |
|---|---|
| `/api/chat/stream` → 404 `text/plain` (маршрута нет) или 405/501 | Вопрос повторяется через legacy `POST /api/chat` `{message}`, ответ показывается целиком. До закрытия панели стриминг больше не пробуется, внизу появляется подсказка «Потоковый режим пока недоступен…». Кнопок 👍/👎 нет (нет `message_id`), `page_context` не отправляется (legacy-контракт его не принимает). |
| `/api/chat/stream` → 404 JSON при переданном `conversation_id` | Диалог не найден: запрос повторяется без `conversation_id`, начинается новый диалог. |
| `/api/chat/brief/stream` → 404/405 | Бриф молча пропускается. |
| feedback → 404/405 | Оценка не сохраняется, но ошибка пользователю не показывается. |
| 401 на любом запросе | Выход и сообщение «Сессия истекла». |
| Поток оборвался без `done`/`error` или молчит 60 с | Ошибка в сообщении и кнопка «Повторить». |

## Тесты

Чистая логика вынесена в `lib/`, тесты на `node:test` лежат в `test/`:

- `lib/sse.js` — парсер SSE: разрезы чанков в любом месте, включая середину UTF-8 и `\r\n`, комментарии, многострочные `data`, таймаут простоя;
- `lib/stream-events.js` — обработка событий `meta/status/delta/sources/action/done/error`;
- `lib/api.js` — стриминг, решение о fallback, actions, feedback, бриф;
- `lib/page-context.js` — фильтрация и очистка контекста страницы;
- `lib/actions.js`, `lib/brief.js`.

```sh
npm test                                        # из корня: client + extension
npm test --workspace @ai-buddy/extension        # только расширение
npm run coverage --workspace @ai-buddy/extension  # покрытие lib/**, порог 80% строк, LCOV в apps/extension/coverage/lcov.info
```

`sidepanel.js` (DOM-обвязка) unit-тестами не покрыт. Его проверяет e2e-тест `tests/e2e/demo.spec.ts` (`npm run test:e2e` при поднятом стенде): тест открывает `chrome-extension://<id>/sidepanel.html` как обычную вкладку.

## Ручная проверка

Расширение проверяется на настоящем backend: соберите его с `BACKEND_ORIGIN` вашего backend и пройдите раздел «3a. Персонаж Бади» в `docs/manual-testing.md`. Демо-страницы для персонажа: `http://127.0.0.1:5173/demo/wiki.html`, `/demo/grafana.html`, `/demo/jira.html`.
