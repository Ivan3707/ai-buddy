# Проверка skeleton · 2026-11-09

Фактически проверено на Windows / Docker Desktop перед первым коммитом:

- Go: `go test ./...` и `go vet ./...` в `golang:1.26-alpine` — успешно; исходники отформатированы gofmt.
- AI: `python -m pytest -q` — 2 теста успешно (локально Python 3.14). Python 3.12-сервис также собран и запущен в Docker. Есть предупреждение стороннего TestClient о будущей замене httpx, тесты проходят.
- Общий JS-клиент: `npm test` — 1 тест успешно.
- `npm run build` — TypeScript, Vite и сборка MV3 успешно.
- `npm audit` — известных уязвимостей не найдено на момент проверки; это не полный аудит безопасности.
- `docker compose up --build -d --wait` — все 3 сервиса healthy.
- `scripts/check_contracts.py` — обе OpenAPI-спецификации валидны; live-ответы Backend проверены по схемам (health, chat, no-match, validation). Для live-проверки требуется `E2E_CREDENTIALS_FILE` с первичным паролем Buddy из Mock HR.
- `npm run test:e2e` — 2 браузерных теста успешно: веб и настоящее распакованное MV3-расширение в Chromium. Веб дополнительно просмотрен по скриншоту.

На этом компьютере 8080 занят другим приложением: тестовый Backend работал на 18080, web на 15173. Порты заданы в локальном игнорируемом `.env`, расширение собрано с `BACKEND_ORIGIN=http://127.0.0.1:18080`, E2E — с `E2E_BASE_URL=http://127.0.0.1:15173`. Остальные сервисы компьютера не изменялись. В чистом окружении используются документированные 8080/5173.

CI отдельно запускает Go race detector и полный прогон на Linux/Python 3.12. Его фактический результат смотрите в GitHub Actions для конкретного коммита.

Не проверены: ручная установка в пользовательский Chrome, реальный RAG/LLM, корпоративные сервисы, нагрузка, production-безопасность и регламент хакатона из недоступного вложения.
