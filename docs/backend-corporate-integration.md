# Backend: Mock HR, роли и корпоративный каталог

Новая пустая PostgreSQL-БД получает единую миграцию Goose `00001_init.sql`. После неё `cmd/init-catalog` создаёт общий и профессиональные чек-листы Backend, Frontend и ML. Команда идемпотентна: совпадающие данные не меняются, несовпадающие отклоняются. Затем `cmd/sync-hr` загружает сотрудников из `data/corporate_employees.json`. Порядок команд и настройки окружения приведены в [README](../README.md).

Mock HR хранит корпоративный ID, email, роль, профессию и назначения. Локальный пользователь сопоставляется по корпоративному ID; legacy аккаунт без него можно однократно связать по email при совпадающей роли. Sync не сбрасывает хеш пароля, локальный ID или прогресс и не удаляет исчезнувших из снимка сотрудников. Новые стажёры получают общий и профессиональный прогресс. Buddy и Teamlead назначаются исключительно из HR снимка. Ручные `POST /api/users` и `PUT /api/buddy/interns/{internID}/teamlead` отсутствуют.

Для новых пользователей Sync генерирует пароль, записывает в БД только Argon2id-хеш и публикует закрытый JSON-файл `-credentials` вне репозитория до commit. Если запись файла не удалась, транзакция откатывается. Если исход commit не подтверждён, файл сохраняется на случай успешного commit. Для Windows используйте `%LOCALAPPDATA%\ai-buddy\credentials\`.

Корпоративный API и права задаются `contracts/backend.openapi.json`. Доступ Buddy и Teamlead к стажёрам ограничен сохранёнными `buddy_id` и `teamlead_id`; actor загружается из проверенного JWT. Заявки на доступ, заметки и события фильтруются по пользователю в SQL. `CORPORATE_MOCK_UNAVAILABLE=1` имитирует недоступность корпоративного сервиса. AI mock получает только текст пользовательского сообщения и не получает пароли или токены.

Существующие БД с историей Goose v8/v9 требуют отдельного плана обновления. Новую единую историю поверх них не применяют автоматически.
