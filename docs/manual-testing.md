# Ручная проверка: все сценарии стажёра и наставника

Чек-лист, чтобы пройти продукт руками и увидеть каждую фичу. У каждого шага указано, что делать, что должно получиться и какую фичу он проверяет.

> **Важно (13.11.2026).** Go-backend пока не реализует стриминг, карточки действий, бриф и кабинет вопросов наставника. До этого бот проверяется через **плейграунд**: тонкий dev-заменитель этих эндпоинтов поверх настоящего AI-сервиса. Веб-приложение сейчас показывает только старый чат, без стриминга и карточек (раздел 4).

## 0. Подготовка

1. **Стенд и плейграунд.** В `.env` должны быть заданы `LLM_*` (OpenRouter). В корне репозитория выполнить:
   ```sh
   docker compose -p ai-buddy --profile playground up -d --build --wait
   ```
   Должны подняться:
   - AI-сервис (внутри Docker);
   - backend на `:18080`;
   - web на `:5173`;
   - плейграунд на `http://127.0.0.1:18090`.
2. **Чат стажёра в браузере (самый быстрый путь):** `http://127.0.0.1:18090/intern`. Это тот же API, что у расширения: бриф, стриминг, источники с цитатами, карточки, 👍/👎. Есть кнопки-примеры и поле «Имитация открытой страницы» для проверки B2 без расширения.
3. **Расширение.** Оно уже собрано под плейграунд в `C:\Hackaton\ai-buddy-extension\apps\extension\dist`. Это рабочая копия ветки `feat/extension-sidepanel`. Порядок:
   - открыть `chrome://extensions` и включить «Режим разработчика»;
   - нажать «Загрузить распакованное» и выбрать папку `dist`;
   - нажать на иконку AI-buddy на панели, справа откроется боковая панель;
   - войти: логин `intern@demo.local`, пароль любой (это плейграунд).
4. **Страница наставника:** `http://127.0.0.1:18090/`. Она обновляется сама каждые 5 секунд.
5. **Сброс состояния.** Плейграунд хранит всё в памяти. Чтобы начать с чистого листа:
   ```sh
   docker compose -p ai-buddy --profile playground restart playground
   ```

**Демо-профиль стажёра:**
- Аня, ML-стажёр, команда «Рекомендации», наставник Олег;
- этап «Погружение» (2 из 4);
- активная задача «Воспроизвести baseline модели рекомендаций»;
- у завершённой задачи «Настроить VPN» есть замечание наставника.

|---|---|---|---|

| 3.9 | Быстро отправить больше 20 сообщений за минуту | Сообщение «Слишком много запросов» | C3 |
| 3.10 | Остановить AI: `docker compose -p ai-buddy stop ai`, задать вопрос, затем `start ai` | Понятная ошибка и кнопка «Повторить», панель не зависает | обработка сбоев |

**Резервная локальная модель (A7, по желанию).** Ollama с `qwen3.5:4b` уже стоит. В `.env` прописать:
```dotenv
LLM_FALLBACK_BASE_URL=http://host.docker.internal:11434/v1
LLM_FALLBACK_MODEL=qwen3.5:4b
LLM_FALLBACK_EXTRA_BODY={"reasoning_effort":"none"}
```
Затем:
1. Временно испортить `LLM_BASE_URL`.
2. Пересоздать ai: `docker compose -p ai-buddy up -d ai`.
3. Задать вопрос по базе. Ответит локальная модель (первый раз 10–20 с, пока она загружается). Действия у неё ненадёжны: это известное ограничение, см. `apps/ai/eval/reports/local-models.md`.

## 4. Наставник (страница плейграунда `:18090`)

| # | Что сделать | Что должно быть | Фича |

| 4.1 | Открыть страницу | Метрики: вопросов, решено ботом, передано наставнику, deflection rate, 👍/👎, действий, «сэкономлено ≈ N мин» | метрики |

## 6. Технические проверки

- `docker compose -p ai-buddy exec ai python -c "import urllib.request;print(urllib.request.urlopen('http://127.0.0.1:8001/metrics').read().decode()[:1500])"` — метрики Prometheus.
- `cd apps/ai && python -m eval.run e2e` (или через Docker, см. `apps/ai/eval/README.md`) — полный eval, около $0.1.
- `python -m eval.run e2e --dataset eval/holdout.jsonl` — отложенный набор.
