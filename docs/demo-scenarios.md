# Демо на 3 минуты

1. Подготовить чистую БД по [README](../README.md): применить миграцию, запустить `cmd/init-catalog` и `cmd/sync-hr`, сохранить созданный вне репозитория файл первичных паролей. Запустить `docker compose -p ai-buddy up --build -d --wait`; открыть веб 127.0.0.1:5173.
2. Войти как `ml.intern@demo.example` с паролем из файла HR Sync. Показать общий и ML-чек-листы, этапы и прогресс. Выйти и войти как `backend.intern@demo.example`: профессиональный чек-лист изменится, общий останется. Прогресс хранится в PostgreSQL и сохраняется после обновления страницы.
3. Спросить «Как оформить отпуск?»; показать инструкцию и источник `hr.example.com/leave`. Объяснить, что заявка не создается.
4. Спросить «Как получить доступ?»; показать другой источник. Спросить `xyz`: явный отказ из-за отсутствия знания.
5. Собрать расширение, загрузить `apps/extension/dist` в Chrome, войти с учётной записью Mock HR и задать тот же вопрос. Ответ идёт через тот же Go Backend.
6. Остановить только AI: `docker compose -p ai-buddy stop ai`. Новый вопрос в вебе/расширении показывает ошибку. Восстановить: `docker compose -p ai-buddy start ai`.

## Автоматические проверки

Unit-тесты проверяют валидацию, retrieval и ошибки AI. Live contract checker проверяет реальные JSON-ответы; для авторизованного чата ему нужен `E2E_CREDENTIALS_FILE` с первичным паролем `buddy@demo.example`. Playwright проверяет веб и загруженный MV3 popup в Chromium. Автоматический тест расширения не заменяет ручную установку в пользовательском Chrome.

Для каждого прогона фиксируйте дату, commit, команды и фактические результаты. Проверки CI видны во вкладке Actions. Полноценное качество RAG/LLM пока не измерено: реальной модели нет.
