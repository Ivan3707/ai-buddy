# Архитектура

```text
React web ── /api (same-origin proxy) ──┐
                                     ├── Go Backend :8080 ── /chat ── FastAPI AI :8001
Chrome MV3 popup ── shared client ─────┘          │                           │
                                              PostgreSQL                    kb.json
```

Go — единственная входная точка бизнес-логики. Python — внутренняя граница retrieval/LLM; интерфейсы не вызывают его напрямую. Веб обслуживает nginx в Compose, Vite при разработке. CORS на Backend не открывается: web идёт через proxy, расширение получает узкое host permission. Содержимое вкладок не передаётся.

Контракт `message → answer/sources/mode` общий для публичного `/api/chat` и внутреннего `/chat`. Go проверяет ввод, ждёт AI не более 10 секунд, отдаёт 502 при ошибке. UI ждёт до 15 секунд. Ответы AI не должны включать исполняемый HTML. `/health` отражает liveness, зависимость проверяется реальным chat smoke-test.

Чек-листы: Backend читает общий и профессиональный каталоги и персональный прогресс стажёра из PostgreSQL. Авторизованные `GET /api/checklists` и `GET /api/progress` обслуживают Web; Buddy и Teamlead видят прогресс назначенных стажёров через `GET /api/staff/interns/{internID}/progress`.

Dockerfile копирует синтетические JSON в контейнеры. После изменения файлов пересоберите соответствующий сервис. Никаких реальных внешних интеграций, учетных данных и сетевых вызовов LLM. Контейнеры AI и backend работают от непривилегированного пользователя; web — стандартный nginx-образ, только локальный порт.

Точки расширения: заменить retrieval внутри AI; добавить канбан и другие представления в web. Сначала согласуйте API в contracts, затем реализацию и тесты. Адреса corporate-сервисов должны поступать только из проверенной базы знаний с allowlist.
