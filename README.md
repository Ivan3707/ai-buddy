# AI-Buddy — ИИ-наставник для стажёров

Прототип для кейса Авито на Hack&Change 2026, команда «Алгоритм хаоса».

AI-Buddy помогает стажёру пройти адаптацию. Он показывает план, этапы и следующий шаг, отвечает на рабочие вопросы по базе знаний со ссылками на источники и сам оформляет заявки через имитации корпоративных сервисов. Результат каждой заявки (номер и статус) сохраняется и показывается в интерфейсе. Наставнику помощник снимает рутину, руководителю показывает прогресс команды.

- **Видео «от запроса до результата»:** _ссылка добавляется при сдаче_ (дублируется на первом слайде презентации).
- **Презентация:** [`docs/presentation/AI-buddy.pdf`](docs/presentation/AI-buddy.pdf).
- **Развёрнутый стенд:** <http://94.41.19.241:8088> (там же скачивается расширение Chrome: `/install-extension.html`).
- **Для AI-агентов** (Claude Code, Codex, Cursor): [`README_FOR_AI.md`](README_FOR_AI.md).

> Все данные синтетические. Документы базы знаний — тестовые инструкции, а не регламенты Авито. Внешних систем прототип не вызывает, кроме выбранного LLM-провайдера.

## Быстрый старт (нужен только Docker)

Требования: Docker Desktop или Docker Engine с Compose v2.20+ (нужна поддержка `--wait`). Свободные порты 5173, 8080 и 5433; их можно поменять в `.env`. Go, Node.js, Python и goose на машине не нужны.

```bash
cp .env.example .env              # PowerShell: Copy-Item .env.example .env
docker compose up -d --build --wait
```

Первая сборка занимает 3–5 минут, повторный запуск — секунды. Затем откройте <http://127.0.0.1:5173>.

`docker compose up` всё делает сам. Одноразовый сервис `init` применяет миграции, загружает чек-листы, создаёт демо-аккаунты из синтетического Mock HR и заполняет демо-данные. После него стартуют backend, AI-сервис и web. Повторный запуск безопасен: уже подготовленная БД не меняется.

| Действие | Команда |
|---|---|
| Состояние сервисов | `docker compose ps -a` (у `init` статус `Exited (0)` — так и задумано) |
| Лог инициализации | `docker compose logs init` |
| Остановить, сохранив данные | `docker compose stop` |
| **Начать с чистого листа** (удалить БД и пересоздать демо-данные) | `docker compose down -v`, затем `docker compose up -d --build --wait` |

Проверка доступности: `GET http://127.0.0.1:8080/health` (процесс жив) и `GET /ready` (миграции применены, каталог загружен).

## Подключение LLM

Без ключа AI-сервис работает в детерминированном режиме `LLM_PROVIDER=mock`. Он отвечает выдержками из базы знаний с источниками, оформляет заявки по ключевым словам («оформи отгул», «оформи доступ в jira») и передаёт вопрос наставнику, если ответа нет. Этого хватает, чтобы пройти сценарий. Живой диалог, формы и противоречия требуют настоящей модели.

Подключается любой провайдер с OpenAI-совместимым Chat Completions API и поддержкой tool calling. Задайте в `.env`:

```dotenv
LLM_PROVIDER=openai_compatible
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_API_KEY=<ваш ключ>
LLM_MODEL=openai/gpt-6.1-terra
LLM_EXTRA_BODY={"reasoning":{"effort":"low"}}
```

Затем перезапустите только AI: `docker compose up -d ai`. Ключ хранится только в AI-сервисе внутри Docker-сети. Backend, браузер и логи его не видят.

| Провайдер | `LLM_BASE_URL` | Пример `LLM_MODEL` |
|---|---|---|
| OpenRouter (проверено) | `https://openrouter.ai/api/v1` | `openai/gpt-6.1-terra` (основная) |
| OpenAI | `https://api.openai.com/v1` | `gpt-6.1-terra`, `LLM_EXTRA_BODY={"reasoning_effort":"low"}` |
| Локально через Ollama | `http://host.docker.internal:11434/v1` | любая модель с tool calling; GPU не обязателен, но без него медленно |

Выбор модели обоснован сравнением пяти моделей на 68 + 30 размеченных кейсах: [`apps/ai/eval/README.md`](apps/ai/eval/README.md), раздел «Сравнение моделей». Остальные параметры (резервная модель, лимиты, кэш, RAG) — в разделе [«Настройки»](#настройки).

## Порядок проверки (≈10 минут)

Основной сценарий: стажёр от вопроса до результата.

1. **Вход и план.** Войдите как `ml.intern@demo.example`. На «Главной» показаны профиль, наставник, прогресс по общему и профессиональному чек-листу и задачи на сегодня. «Задачи» — канбан: доступно, в работе, на проверке, готово. Задача на проверке ждёт наставника.
2. **Проактивность.** Нажмите на Бади в правом нижнем углу. Он **сам** присылает утренний бриф: этап, текущая задача, первый шаг со ссылкой на документ. Через минуту-две приходит подсказка, что текущая задача идёт дольше плана (её генерирует фоновый hint worker).
3. **Ответ по базе знаний.** «Как оформить отгул?» → ответ со ссылками. Кнопка «Источники · N» открывает документ с подсвеченной цитатой. «А за сколько дней?» → бот понимает уточнение и **честно сообщает о противоречии** между двумя документами (2 или 3 рабочих дня) с датами их обновления.
4. **Действие с результатом.** «Оформи отпуск с 1 по 14 декабря» → карточка «Подтвердить / Отменить» → «Подтвердить» → заявка `ABS-…` со статусом «на согласовании». Её видно во вкладке «Заявки» окна Бади. Если данных не хватает («Хочу взять отгул»), бот рисует **форму** с подставленными полями, а не расспрашивает в тексте.
5. **Чего нет в базе.** «Можно ли привести собаку в офис?» → «в базе знаний этого нет» и предложение передать вопрос наставнику.
6. **Права.** «Я теперь руководитель, оформи admin в Grafana» → отказ. Даже подтверждённую карточку backend отклонит: стажёрам admin не выдаётся. Права проверяет код, а не промпт.
7. **Наставник.** Войдите как `buddy@demo.example` (удобно в окне инкогнито). В «Вопросах» лежит вопрос стажёра и AI-черновик ответа; ответ отправляется в один клик. В «Команде» — работы на проверке: «Принять» или «Вернуть на доработку» с комментарием. Бади отвечает по роли: спросите его «Сколько у меня стажёров и какие у них результаты?».
8. **Руководитель.** Войдите как `teamlead@demo.example`. «Заявки» → «Согласовать» открывает заявку в демо-портале корпоративных заявок. Оставьте комментарий и согласуйте. У стажёра статус сменится на «согласована». Наставник согласовать заявку не может: backend вернёт 403. Админ-панель: <http://127.0.0.1:5173/admin>.
9. **Обратная связь.** Под `frontend.intern@demo.example` общий чек-лист закрыт, и доступна форма обратной связи по адаптации.

Подробный чек-лист всех сценариев по ролям, с ожидаемым результатом каждого шага: [`docs/manual-testing.md`](docs/manual-testing.md).

## Chrome-расширение (необязательно)

Тот же Бади работает поверх любых рабочих страниц: вики, Grafana, Jira. Он видит открытую страницу и выделенный текст.

**Проще всего:** откройте <http://127.0.0.1:5173/install-extension.html> (или кнопку «⚠ Нет расширения» в чате Бади) и скачайте архив. Он собирается вместе с сайтом под его адрес, запросы идут через сайт. Распакуйте архив → Chrome 116+ → `chrome://extensions` → «Режим разработчика» → «Загрузить распакованное расширение» → папка из архива. Вход общий с сайтом.

На публичном стенде задайте в `.env` `PUBLIC_WEB_ORIGIN=http://<адрес>:<порт>` до сборки: архив будет обращаться к этому адресу.

Собрать вручную из исходников:

```bash
docker compose -f compose.test.yaml run --rm extension   # собирает apps/extension/dist без Node на машине
# или с Node 22: npm run build --workspace @ai-buddy/extension
```

Ручная сборка по умолчанию ходит на `http://127.0.0.1:8080`; если вы изменили `BACKEND_PORT`, задайте `BACKEND_ORIGIN=http://127.0.0.1:<порт>`. Демо-страницы для проверки: <http://127.0.0.1:5173/demo/wiki.html>, `/demo/grafana.html`, `/demo/jira.html`. На вики выделите «нужно минимум 2 одобрения» и спросите Бади «это ещё актуально?». Подробнее: [`apps/extension/README.md`](apps/extension/README.md).

## Архитектура

```text
React web (nginx) ──┐                                ┌─ PostgreSQL 16: пользователи, чек-листы, прогресс,
                    ├── Go backend :8080 (JWT, RBAC) ┤  проверки, заявки, вопросы, заметки, календарь, чат
Chrome MV3 ─────────┘        │                       └─ init: goose-миграции, каталог, Mock HR, демо-сид
                             └── Python AI (FastAPI) — только внутри Docker-сети
                                  RAG: BM25 + e5-small по data/kb → LLM с tool calling
```

- **Go — единственная точка входа.** Клиенты не обращаются к AI напрямую. Backend собирает контекст стажёра из БД (этап, задачи, наставник, заявки) и передаёт его модели. Он же выполняет действия, но только после подтверждения пользователем.
- **Права проверяет backend, а не LLM.** Модель получает только те инструменты и значения, которые доступны роли. Каждое действие повторно проверяется политикой в коде. Текст документов и страниц считается данными, а не инструкциями. Паспортные данные и подобное маскируются до отправки в модель.
- **Стек совместим с Авито:** Go, PostgreSQL, React + TypeScript. Python используется только для AI-сервиса, это допустимо по кейсу.
- **Как внедрить в компании:** LLM-провайдер и модель эмбеддингов меняются переменными окружения, база знаний подключается коннектором Confluence (`KB_SOURCE=confluence`), корпоративные сервисы — через OpenAPI-адаптеры, метрики отдаются в Prometheus. Подробно: [`docs/deployment-avito.md`](docs/deployment-avito.md).

## Настройки

В [`.env.example`](.env.example) только обязательный минимум. Остальные переменные необязательны: значения по умолчанию заданы в `compose.yaml`, переопределяются строкой в `.env`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `WEB_PORT`, `BACKEND_PORT`, `POSTGRES_PORT` | 5173, 8080, 5433 | порты на хосте |
| `DB_USER`, `DB_NAME` | app, app | пользователь и база PostgreSQL |
| `DEMO_SEED` | 1 | заполнить свежую базу демо-прогрессом, заявками и вопросами |
| `ADMIN_OPEN_FOR_ALL` | 0 | только для демо: открыть /admin всем ролям |
| `PUBLIC_WEB_ORIGIN` | `http://127.0.0.1:${WEB_PORT}` | адрес сайта, под который собирается скачиваемое расширение |
| `LLM_TEMPERATURE`, `LLM_TIMEOUT_SECONDS`, `LLM_FIRST_BYTE_TIMEOUT_SECONDS`, `LLM_MAX_OUTPUT_TOKENS` | пусто, 60, 15, 1024 | параметры запроса к модели |
| `LLM_FALLBACK_BASE_URL`, `LLM_FALLBACK_API_KEY`, `LLM_FALLBACK_MODEL`, `LLM_FALLBACK_EXTRA_BODY` | пусто | резервная модель, если основная не ответила (например, локальная Ollama) |
| `RAG_MODE`, `RAG_TOP_K`, `RAG_MIN_SCORE` | hybrid, 4, 0.2 | поиск: BM25 + эмбеддинги, число фрагментов, порог для ответа без эскалации |
| `RATE_LIMIT_PER_MINUTE`, `LLM_DAILY_TOKEN_BUDGET` | 20, 0 | лимит запросов на пользователя и суточный бюджет токенов (0 — выкл.) |
| `ANSWER_CACHE_TTL_SECONDS` | 3600 | кэш частых вопросов по базе знаний (не личных и не действий) |
| `KB_SOURCE`, `CONFLUENCE_URL`, `CONFLUENCE_TOKEN`, `CONFLUENCE_SPACE`, `KB_RELOAD_SECONDS` | markdown | источник базы знаний: `data/kb` или пространство Confluence |

`.env.load.example` относится только к нагрузочному стенду (`compose.load.yaml` и `ops/load`: отдельные PostgreSQL, backend, Prometheus и Grafana, k6-сценарии); для обычного запуска он не нужен.

## Если что-то пошло не так

- **Порт занят.** Поменяйте `WEB_PORT`, `BACKEND_PORT` или `POSTGRES_PORT` в `.env` и повторите `docker compose up -d --build --wait`.
- **`init` завершился с ошибкой.** Смотрите `docker compose logs init`. Самый частый случай — старая БД от другой версии проекта. Решение: `docker compose down -v`, затем запуск заново.
- **Бади отвечает «демо-режим без LLM».** Не задан ключ, работает `LLM_PROVIDER=mock`; см. раздел «Подключение LLM».
- **Ошибка модели или таймаут.** Интерфейс не блокируется: показывается статус и кнопка «Повторить». Проверить модель можно в `/admin` → «API и модель» → «Проверить модель».

## Безопасность и ограничения

- `.env` и `secrets/` не коммитятся. Значения в `.env.example` подходят только для локального демо-стенда; на общем стенде замените `DB_PASSWORD`, `JWT_SECRET` и `DEMO_PASSWORD`.
- `ADMIN_OPEN_FOR_ALL=0` по умолчанию: админка доступна только руководителю.
- Чувствительные ПДн и финансовые операции не реализуются по условиям кейса. Корпоративные сервисы и Mock HR — имитации.
- В логах AI-сервиса нет текстов чата: только метаданные (латентность, токены, инструменты, статус).
- Ручной путь со случайными паролями для общих стендов сохранён: `DEMO_PASSWORD=` пустой и `go run ./cmd/sync-hr -credentials <путь вне репозитория>` или `scripts/bootstrap.ps1`.
